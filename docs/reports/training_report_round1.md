历史实验使用的验证集合大小和来源组成不同。不同划分的宏 F1 不能直接用于模型排名；应优先比较相同验证 ID 或相同来源评测上的结果。以下保留各轮实验记录，本轮匹配划分结果见文末上下文执行实验。

## 轻量权重对照

在按对话分组的 5 折交叉验证中，将 `clarify` 类权重设为 1.5 后，宏平均 F1 从 0.862 变为 0.859，准确率从 0.855 变为 0.850；`clarify` 召回率从 0.715 提升至 0.815，ShARC 子集的 `clarify` 召回率从 0.43 提升至 0.63。权重设为 2.0 时召回率更高，但 `decide` 召回率明显下降，因此采用 1.5 作为折中。

## 如何解读

这是流程基线，不是可靠的真实中文效果估计。中文输入大部分由本地机器翻译生成；SWE-bench 训练文本还使用了中文路由指令加 Issue 标题，因此 `codex` 分数容易受构造方式影响。留出数据仍来自相同公开数据源，覆盖面有限。加权后 `clarify` 召回有所提高，但 ShARC 上仍有明显错误。

因此模型概率尚未校准，也不应自动派发任务。下一轮优先加入自然中文的真实请求；重点增加 `clarify` 边界样本，然后再用来源独立、按对话分组的留出集评估。

训练时必须显式使用 `--include-machine-translation-drafts`。普通训练命令仍不会把这些 `reviewed: false` 的草稿当作正式标注。

## 按意图微调的语义模型

- 产物：`artifacts/decisioner_semantic_draft/model_int8.onnx`，运行时使用 ONNX Runtime CPU。
- 基座：BAAI/bge-small-zh-v1.5；最大输入长度 192 tokens，微调 3 轮，未使用类别权重偏置。
- 当前默认模型训练集：600 条机器翻译路线候选、272 条合成中文意图样本和 40 条合成分句样本；未使用 117 条来源分组留出数据训练。
- 来源分组留出集：117 条，准确率 89.7%，宏平均 F1 0.897。`decide`、`clarify`、`codex` 的召回率依次为 0.800、0.911、0.973。
- 35 条开发探针在最终 ONNX 运行时上有 34 条预测正确。该探针曾用于错误分析并影响后续补充样本，因此不能视为独立测试成绩或真实场景准确率。
- ONNX 动态 INT8 量化文件约 57.5 MB；含分词和一次近期上下文的单条 CPU 热推理约 3 ms（本机测量，速度会随硬件变化）。

这些结果只是实验信号：源留出集仍来自训练所用公开数据集的相同分布；中文训练文本包含机器翻译和合成样本。用户请求“那让模型学会识别意图”和“给我在项目中训练模型”已作为训练样本，因此对这些原句的预测属于训练内结果，不能拿来当独立验证。开发探针也曾影响补充样本；真实效果要用新收集、未参与开发的对话数据再评估。此前发现的短确认误判现在由窄范围上下文策略处理，仍需真实对话数据验证泛化。

本轮补入了直接启动训练、修复并运行脚本、把功能写入仓库等 Codex 上下文样本，同时保留“只问方案/解释、不执行”的对照。当前模型把未加入训练集的“继续加强 Codex 判断能力”判为 `codex`，把“Codex 路由通常怎么提高准确率？”判为 `decide`。单句和对话上下文的 Codex 判断仍需新的真实样本验证。

### 多分句输出

推理结果增加 `clause_analysis` 数组，记录每个分句的原文、路由、分数和规则覆盖原因；复合请求的 `action` 按澄清优先、其次 Codex、最后直接回答汇总。当前分句边界由轻量标点/连接词切分器确定，分类器结合完整原句上下文判断单个分句。40 条分句训练样本覆盖“先解释、再修改”“修复并说明”等混合请求；切分器没有独立标注测试集，复杂嵌套句、转折句和省略主语仍需真实数据评估。

当前 `try_router.py` 默认加载语义模型。字符 n-gram 模型保留作为基线，可通过 `python -m light_decider.predict` 单独使用；运行时策略补充了缺失指代、纯比较/解释、技术验收陈述和上下文确认的窄范围判断，不用通用动作词表强行覆盖为 `codex`。所有概率仍未校准，自动派发保持关闭。

### 来源扩充与截断候选

- 训练输入长度分析发现：原 600 条来源样本中有 54 条超过 192 tokens，其中 ShARC 占 53 条；36 条 ShARC 样本的当前问题会被右截断整段裁掉。该现象只在训练数据上统计。
- 尝试了两个兼容旧模型的候选设置：左截断、192 tokens 的内部宏 F1 为 0.884；右截断、320 tokens 为 0.875。二者均低于当前默认基线 0.897。
- 另外从官方 ShARC train 生成 300 条未人工审核的机翻弱标签，按 300 棵未使用的树分组并保持两类均衡。加入后总来源样本 900 条、分组验证 184 条，最佳宏 F1 为 0.854；`decide/clarify/codex` 召回率为 80.3%/76.7%/100%。扩充候选没有被导出或启用。
- 这些实验说明单纯增加同域的机翻弱标签或放宽 token 长度没有提高整体内部验证表现。默认权重和 192-token 右截断保持不变；新增训练入口只用于后续实验。官方 ShARC dev 曾作为一次性来源留出冻结；2026-11-03 又按候选对照计划比较了默认模型与当前候选，得到 61.7% 和 76.7%。该集现已用于模型比较，后续仍不应按逐条错误调参。

### 路由实现运行开销对照

- 本机 CPU 对 45 条 Codex 开发回归集进行热推理对照：字符 n-gram 基线 39/45，BGE 语义版 45/45。该集合已参与策略开发，不能据此宣称真实流量准确率。
